# 网络搜索规范

## 何时搜索

- 涉及最新信息、外部事实、版本差异、官方文档、第三方服务、论文、标准、政策时，应搜索。
- 如果用户明确要求“联网查”“最新”“官方资料”“引用来源”，必须搜索。
- 如果信息已存在于当前工作区，优先读取本地文件，不要用搜索替代代码上下文。
- 对代码实现、项目结构、配置、错误日志等本地上下文问题，先查本地文件；只有需要外部资料验证时再搜索。

## 搜索规则

- 优先使用 MCP 搜索工具，尤其是 Tavily、Jina。
- 不要默认使用本地 Web 搜索或浏览器式搜索。
- 技术类主题默认使用英文关键词搜索，包括代码文档、API、开源库、框架、算法、论文、协议、RFC、云服务、错误排查。
- 只有中文社区内容、国内产品、国内政策、中文平台规则、中文报错原文、中国大陆语境资料，才优先使用中文搜索。
- 如果中文搜索结果质量差，应改用英文搜索交叉验证。
- 如果英文搜索无法覆盖中文语境，再补充中文搜索。

## 工具优先级

- 第一优先级：Tavily、Jina 等 MCP 搜索/提取工具。
- 第二优先级：针对已知权威 URL 做页面提取。
- 第三优先级：普通 WebFetch 或本地 Web 搜索，仅作为 fallback。
- 如果 MCP 工具不可用，要说明已降级到其他搜索方式。

## 来源质量

- 优先官方文档、源码仓库、release notes、标准文档、论文、厂商文档。
- 社区博客、论坛、问答站点只能作为辅助证据，除非任务本身就是调研社区经验。
- 对版本敏感、实现相关、安全相关内容，至少交叉验证来源。

## 输出要求

- 外部事实影响结论时，给出来源名称或 URL。
- 来源冲突、内容过旧、无法确认时，明确说明不确定性。
- 不要为常识性内容过度引用。
- 如果搜索语言选择会影响结果，应简短说明使用了英文或中文查询。
- 如果发生工具降级，应简短说明原因。

## 禁止事项

- 不要习惯性用中文搜索通用技术问题。
- 不要用 SEO 博客替代官方文档。
- 不要只看一个搜索结果就得出高影响结论。
- 不要在本地代码足以回答时盲目联网。
