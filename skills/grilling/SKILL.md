---
name: grilling
description: 对用户的计划、决定或想法进行无情的盘问。当用户想要对他们的想法进行压力测试，或者使用了任何“盘问（grill）”相关的触发词时使用。
---
无情地盘问用户，直到你们达成共识。将此映射为一棵**设计树（design tree）**：每个决定都会分支成依赖于它的后续决定。
按**轮次（rounds）**推进这棵树。**前沿（frontier）**是指那些先决条件已经确定的所有决定：即你_现在_就可以提出的问题，而无需猜测你尚未听到的答案。在同一轮中问出所有处于前沿的问题：为每个问题编号，并给出你的推荐答案。然后等待用户的回答，再进入下一轮。
每个问题的格式应如下所示：

```
❓ Q1 - <问题标题>：<问题正文，可能是多个段落，包括多个选项>

➡️ <你的推荐答案>
```

用户每一轮的回答都会重塑这棵树：已解决的决定会将前沿向外推进，并解锁依赖于它们的问题。重新计算前沿，并进行下一轮提问。如果一个问题的答案依赖于本轮中仍未解决的另一个问题，那么它属于_后续_轮次，而不是本轮。

寻找_事实_是你的工作，绝不是用户的。当前沿问题需要来自环境（文件系统、工具等）的事实时，派遣一个子智能体（sub-agent）去寻找它；不要向用户询问任何你自己可以查到的东西。不要因此而阻塞：正在进行的探索是一个未解决的先决条件，因此只有它下游的问题需要等待子智能体的报告；现在就问出前沿中的其他问题。_决定权_在用户手中：将每个决定交给他们并等待。

当前沿为空时，会话结束：设计树的每个分支都已访问，没有任何被默默假设的内容。在用户确认你们已经达成共识之前，不要采取任何实际行动。

每次向用户提问时，必须根据当前运行的 agent 使用对应的提问工具，而不是输出纯文本：

- **OpenCode**：使用 `question` 工具
- **Claude Code (CC)**：使用 `AskUserQuestion` 工具
- **Codex (OpenAI Codex CLI)**：使用 `ask_followup_question` 工具
